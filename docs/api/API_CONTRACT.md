# ResQPH API contract

**Status:** Completed and verified Phase 1 contract baseline
**Base path:** `/api/v1`
**Last updated:** 2026-09-22

## Contract rules

- JSON property names use `snake_case` across the API and Python backend.
- Identifiers are opaque strings; clients must not derive meaning from their format.
- Timestamps use ISO 8601 UTC and end in `Z`.
- Geographic points use GeoJSON longitude-first coordinate order.
- Lists use stable pagination before production-sized data are introduced.
- Synthetic or controlled data include their source type and observation/scenario timestamp.
- The OpenAPI document generated by FastAPI must agree with this contract before Phase 2 exits.

## Prototype role simulation

Protected demo operations accept:

- `X-Demo-User-Id`
- `X-Demo-Role`: `citizen`, `volunteer`, `rescuer`, or `coordinator`

The backend validates whether the role may perform the operation. These headers are a prototype control and must never be described as production authentication.

## Common error envelope

```json
{
  "error": {
    "code": "invalid_transition",
    "message": "Mission cannot move from assigned directly to completed.",
    "details": [
      {
        "field": "status",
        "reason": "expected en-route"
      }
    ],
    "request_id": "trace-opaque-id"
  }
}
```

| HTTP status | Meaning |
|---|---|
| `400` | Malformed or unsupported request outside schema validation |
| `403` | Simulated role is not allowed to perform the operation |
| `404` | Requested record does not exist or is unavailable to the role |
| `409` | Valid input conflicts with current assignment, version, or lifecycle state |
| `422` | Request fails field or domain validation |
| `503` | Required dependency is unavailable; fallback was not possible for this operation |

## Core endpoints

### Health

`GET /health`

Returns application health without exposing credentials or internal connection details.

### Create rescue request

`POST /rescue-requests`

Allowed role: `citizen`.

```json
{
  "location": {
    "address": "Block 5 Lot 21 Jhocson St., Sampaloc, Manila",
    "point": { "type": "Point", "coordinates": [120.9946, 14.6042] },
    "landmark": "Sanitized demonstration landmark"
  },
  "headcount": 4,
  "vulnerabilities": ["infant", "senior"],
  "medical_needs": true,
  "medical_details": "Sanitized demonstration note",
  "reported_flood_level": "high",
  "situation_summary": "Controlled rescue demonstration"
}
```

Success: `201 Created` with the stored request, `status: "pending"`, `version: 1`, and server timestamps.

### List and retrieve rescue requests

- `GET /rescue-requests?status=pending&limit=20&cursor=...`
- `GET /rescue-requests/{request_id}`

Citizens see their simulated requests. Coordinators see the queue. Rescuers see request detail only through an assigned mission.

### Cancel pending request

`POST /rescue-requests/{request_id}/cancel`

Allowed role: owning `citizen` or `coordinator`. Requires `reason` and expected `version`. Returns `409` when an incompatible active transition has already occurred.

### Assign rescue team

`POST /rescue-requests/{request_id}/assignment`

Allowed role: `coordinator`.

```json
{
  "team_id": "team-alpha",
  "expected_request_version": 1
}
```

Success: `201 Created` with the mission and updated request summary. Request transition, mission creation, team availability, and history records form one consistency boundary.

### Retrieve missions

- `GET /missions?assigned_to=me&status=assigned,en-route,arrived`
- `GET /missions/{mission_id}`

Mission detail includes request summary, sanitized citizen information needed by the assigned team, latest route result when available, status history, data-source labels, and synchronization metadata.

### Update mission status

`POST /missions/{mission_id}/status-events`

Allowed role: assigned `rescuer`; completion may also be accepted from `coordinator`.

```json
{
  "event_id": "client-generated-idempotency-key",
  "new_status": "en-route",
  "expected_mission_version": 1,
  "client_recorded_at": "2026-09-21T04:00:00Z",
  "source": "online",
  "note": "Sanitized optional note"
}
```

The same `event_id` must not create duplicate history. Valid offline synchronization changes `source` to `offline-sync` and remains subject to the same transition and version rules.

### Submit hazard report

`POST /hazard-reports`

Allowed roles: `volunteer`, `rescuer`, or `coordinator`.

Required fields: location point, hazard type, severity, observed time, source type, and optional sanitized note. New volunteer/rescuer reports are unverified until coordinator review.

### Verify hazard report

`POST /hazard-reports/{hazard_id}/verification`

Allowed role: `coordinator`. Verification does not convert a controlled or historical report into live information.

### Request route

`POST /routes/evaluate`

Allowed roles: `rescuer` or `coordinator`. The request and response follow [the routing contract](../routing/ROUTING_CONTRACT.md). Routing may return a successful route, a documented no-route result, or an unavailable error when the deterministic engine itself cannot run.

## Phase 2 contract checks

- Pydantic schemas reproduce the examples and constraints.
- OpenAPI exposes the documented endpoints and response codes.
- Role simulation denies prohibited operations.
- Assignment and transition conflicts return `409` without partial writes.
- The core lifecycle works when routing and ML adapters are unavailable.
- Contract tests use sanitized fixtures only.
